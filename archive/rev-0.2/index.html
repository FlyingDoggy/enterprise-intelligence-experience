01

THE FELT LAYER

治理不应该被感到是枷锁，
而应该被感到是方向感。

选择一种体验承诺，查看用户原始焦虑、设计机制和最终感受。

02

BEFORE / AFTER

不是多一个AI入口，
而是改变工作的容器。

BEFORE一个聪明的Chat
  • 答案、筛选器和图表各自维护状态
  • 用户通过结果猜测AI理解
  • 追问覆盖原结论
  • 建议、批准和执行含义模糊
  • 失败后人从头调查
AFTER一个稳定的Work Object
  • Goal、Context、State和Owner常驻
  • 变更先成为可预览Patch
  • Claim绑定Evidence，追问创建Branch
  • Prepare、Approve、Execute和Outcome分开
  • Handoff保留Context与Work Done

01 · CANONICAL ARCHITECTURE

THE SOURCE OF TRUTH

一个Kernel。
两种Contract。
三套治理生命周期。

技术架构决定AI能做什么；体验架构决定人如何理解、控制并对它负责。

02

SHARED EXPERIENCE KERNEL

所有场景共享八个稳定对象。

Patch、Gate、Receipt、Revision和Handoff作用于这些对象，但不是第二套Kernel。

03

TWO INTERACTION CONTRACTS

共享对象，不共享责任节奏。

04

ORTHOGONAL SEMANTICS

可信、允许、低风险和已执行，
从来不是同一件事。

七个轴独立存储和表达。任何一个状态都不能自动推出另一个状态。

05

THREE GOVERNED LIFECYCLES

发布、行动和规则变更分别治理。

06

COLLABORATIVE INTELLIGENCE

ChatBI是一个Family中的Pattern，
不是Collaborative的全部。

ANALYTICAL INTELLIGENCE · FIVE DIMENSIONS

Work Question × Initiation × Control Posture × Surface / Artifact × Action Authority

02 · PATTERN SPECIMEN LIBRARY

FROM PRINCIPLE TO BEHAVIOR

Pattern不是视觉模板，
而是可验证的体验契约。

固定的是User Goal、Work Object、状态、权限和恢复路径；可扩展的是领域内容、品牌和信息密度。

02

INTERACTIVE SPECIMENS

不是讲述治理，
而是让用户亲手验证它。

SIMULATION · NO EXTERNAL ACTION
03

PATTERN ANATOMY

每个Pattern都必须回答同一组问题。

03 · REFERENCE JOURNEYS

CONTROLLED HANDOFFS

对象彼此关联，
但不会偷偷变身。

Analysis、Decision、Action和Case共享Root与Trace，同时保留自己的Owner、Revision和Lifecycle。

02

HANDOFF ENVELOPE

交接不是一句“转人工”，
而是一份可继续工作的上下文包。

04 · UX ACCEPTANCE

FROM PRINCIPLES TO TESTS

技术验收之外，
增加Experience Gate。

企业AI不仅要能运行，还要让用户正确理解状态、控制后果并在失败后继续工作。

02

READER TESTING

文档不是作者看懂了就算完成。

无上下文读者必须能够正确复述核心模型，并识别治理状态。

03

2027 UX WORKSTREAM

UIUX是横向能力，不是Front-end附属项。

PRODUCTION DESIGN SYSTEM TRIGGER

至少两个真实消费者、稳定的语义轴与Lifecycle、无领域分支的公共Schema，以及明确的API、Owner、Version和Migration。
