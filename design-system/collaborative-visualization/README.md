# Collaborative Intelligence 数据可视化扩展

> EIX Core Design System · Candidate Extension · v0.1.0

这组文件把 Collaborative Intelligence 中“提出问题、形成结果、解释依据、继续分析”的数据表达要求，转换为设计与开发可以共同执行的契约。

它不是一套新的业务架构，也不是图表组件包。它补充的是：

- 设计侧如何从分析任务选择表达形式；
- 图表必须携带哪些口径、限制与依据；
- 哪些数据条件不满足时不得生成某类图表；
- 图表、表格、文字摘要和依据如何引用同一个结果对象；
- 开发侧如何用确定性规则生成、校验和渲染图表规格。

## 与Claude补充材料的对照结论

### 直接吸收并重新表达

1. **图表色和状态色隔离**
   - 状态色表达“已验证、警告、阻断”等含义；
   - 系列色只表达数据身份；
   - 状态覆盖必须同时使用文字、符号或形状。
2. **确定性图表路由**
   - 图表形态由分析任务、数据形状和前置条件决定；
   - 大语言模型可以解释推荐理由，但不得自由决定数据编码。
3. **先判断是否需要图表**
   - 单值用关键数字；
   - 逐位核对用交叉表；
   - 高基数类别优先表格、强调式或小倍数。
4. **每类图表都有停止条件**
   - 贡献不完备时不画瀑布图；
   - 历史不足时不画预测或异常带；
   - 粒度不一致时不画关系图；
   - 口径不可比时不画基准差异。
5. **图表口径行**
   - 指标、期间、版本、单位、数据粒度和更新时间必须随图表出现。
6. **图表必须有等价文本或数据表**
   - 提示气泡是补充，不是唯一信息来源。
7. **点击默认只选中**
   - 后续的筛选、下钻、比较和解释由用户明确触发。

### 当前覆盖

- 14类工作问题和36种默认、替代或流程表达；
- 12种完整可交互结果组件；
- 22种图形图谱，包括瀑布、桑基、热力、异常带、哑铃、漏斗、流程路径、任务时间轴和受控帕累托；
- 五槽系列色、七阶顺序色、七阶发散色和Actual / Plan / Forecast线型语法。

### 在EIX中改写后吸收

1. 原材料把 `teal / amber / red` 固定映射为若干状态。EIX保留“状态色与系列色隔离”的原则，但使用现有 `semantic.*` 和 `eix.*` 语义轴，不引入第二套状态命名。
2. 原材料把系列上限写成五个颜色槽。EIX保留五槽硬上限，但把“超过五个”处理写进 Chart Router，不允许调用方自行补色或循环用色。
3. 原材料的 `ChartFrame` 只包含标题、口径和摘要。EIX扩展为完整 `ChartBlock`：结论、口径、图形、限制、依据、数据表和后续分析入口引用同一 `resultRef`。
4. 原材料把帕累托图作为双Y轴唯一例外。EIX不设通用例外：默认使用共享X轴的上下两图；只有经过具名设计评审的帕累托实现，且累计轴固定为0–100%，才允许单图呈现。
5. 原材料主要覆盖图形选型。EIX补充 Collaborative Intelligence 特有的工作问题、结果状态、数据叙事、依据失效和追问分支规则。

### 不吸收

- 不复制 `@gax/ui` 的React接口或未授权源码；
- 不使用“高置信度等于可执行”之类的跨语义推导；
- 不把颜色校验报告当作永久事实，任何色值变更都必须重新验证；
- 不把所有图形都包装为卡片，也不把“图表越多”当作分析越完整；
- 不允许叙事中的数字独立于结果对象再次生成。


```bash

```


## 成熟度边界

当前产出是实现级参考，不是已发布的 `@eix/charts` 包。进入生产组件阶段前仍需完成：

- 使用真实语义层元数据验证字段兼容；
- 为目标图表引擎建立渲染与截图回归；
- 使用真实数据密度做标签碰撞和性能测试；
- 将色觉、对比度和键盘行为检查接入持续集成；
- 明确图表规格、结果对象和依据服务的版本兼容策略。
