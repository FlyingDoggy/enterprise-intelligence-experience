# EIX 2.0 Rev 0.5 读者测试方案

> 目的：验证没有项目背景的读者能否理解这套架构。  
> 测试对象：Rev 0.5核心架构章程、核心设计系统、智能体验设计指导与静态参考站。  
> 规则：测试前不得向参与者透露预期答案。

## 1. 参与者

每类至少招募两名读者：

1. 管理层或业务负责人；
2. 产品或体验设计人员；
3. 工程、数据或治理人员。

主持人可以说明网站如何操作，但不能预先解释EIX术语。

## 2. 测试过程

### A. 五分钟无辅助阅读

以“快速阅读”打开`#/brief`。五分钟后关闭页面并提问：

1. EIX 2.0要解决什么问题？
2. Process Intelligence与Collaborative Intelligence共享什么？
3. 两种人机协作约定有什么区别？
4. 用户始终应该能够理解或控制哪三件事？
5. 哪份文档是架构事实来源？

### B. 状态语义区分

展示一组状态：

- 结论陈述：预测；
- 依据：已验证；
- 风险：高、不可逆；
- 权限：禁止；
- 人工智能可推进范围：仅建议；
- 工作状态：草稿。

询问：

1. 这条结论陈述是不是事实？
2. 这项业务操作能否使用该依据？
3. 业务操作能否执行？
4. 每个答案分别由哪个标签决定？

通过条件：参与者不会从“依据已验证”推导权限、人工智能可推进范围或工作状态。

### C. 工作结果、目标与状态区分

打开“可信回答（最短路径）”旅程并提问：

1. 已交付的工作结果是否自动成为交付物？
2. 用户阅读后离开，是否代表目标一定完成？
3. 这项任务是否必须产生决策或业务操作？

通过条件：参与者能说明工作结果可独立引用；用户离开记录为“未观测”；可信回答可以在不产生交付物、决策或业务操作时合法结束。

再打开“受控业务操作”交互示例，并停在“已批准”：

1. 业务操作是否已经执行？
2. 下一项合法状态是什么？
3. 业务操作执行状态在哪里显示？
4. 后续业务改善在哪里显示？

通过条件：参与者能回答“尚未执行”“下一步为已排队”“执行回执 / 业务操作状态”，并能指出独立的“业务成效回执”。

### D. 交互模式选择

给出四个场景，不提示交互模式名称：

1. 一份已发布简报依赖已经过期的依据快照；
2. 一个流程事项执行五步后，在第三步失败；
3. 用户希望改变范围，但不覆盖当前修订版本；
4. 一次人工异常判断可能沉淀为可复用规则。

预期选择：

1. 依据回执 + 发布校验；
2. 恢复与回退工作区 + 执行回执，业务成效仍是关联观察；
3. 意图与变更预览，并创建分支或撤回变更；
4. 规则提案与变更审批。

### E. 跨约定连续性

打开两条参考旅程，要求参与者解释：

1. 为什么分析对象与流程事项不是同一个对象；
2. 一次交接必须携带什么；
3. 谁负责下一项决策；
4. 权限被禁止时会发生什么。

通过条件：参与者能指出类型明确的工作对象关联、上下文 / 依据 / 管控策略连续性、明确的决策负责人，并且不会把交接理解为静默执行。

### F. 设计系统与设计指导边界

分别打开`#/design-system`和`#/guidance`，给出六项内容：

1. 按钮禁用状态；
2. 焦点环；
3. 依据回执；
4. 发布校验；
5. 表格响应式行为；
6. 规则提案生命周期。

预期答案：

- 核心设计系统负责1、2、5；
- 智能体验设计指导负责3、4、6；
- 核心架构章程继续拥有3、4、6所引用的语义和生命周期不变量。

通过条件：参与者不会把依据、权限或业务生命周期放进核心通用组件。

### G. 能力、权限与业务操作边界

打开`#/guidance/shared/S09`，依次切换“完整”“缺少范围”“权限漂移”和“已暂停”：

1. “完整”是否代表业务操作已经获批？
2. 缺少范围时，界面应该怎样处理？
3. 哪些检查仍属于业务操作执行前检查？

通过条件：参与者能说明能力快照是版本化声明，不是授权；在不可执行时仍保留提案和升级路径；执行主体、作用对象、参数、管控策略、权限与风险仍需重新校验。

### H. 主题、明暗模式与语义稳定性

打开颜色基础规范，切换中性主题 / EIX主题与浅色 / 深色模式：

1. 主题变化时，什么会改变？
2. 明暗模式变化时，什么会改变？
3. 两者是否可以改变权限、风险、状态或组件行为？

通过条件：参与者能说明主题改变品牌表达，明暗模式改变视觉映射；两者都不改变交互约定或业务语义。

## 3. 评分

| 维度 | 通过口径 | 目标 |
|---|---|---:|
| 架构 | 能解释共享工作模型是任务覆盖范围 / 关系模型，并能区分两种人机协作约定 | ≥90% |
| 语义 | 能区分结论陈述、依据、风险、权限和人工智能可推进范围 | ≥85% |
| 状态 | 能区分工作结果、目标完成判断、业务操作状态和业务成效 | ≥95% |
| 交互模式 | 能为场景选择预期交互模式组合 | ≥85% |
| 文档身份 | 能区分核心规范、配套说明和候选规范 | 100% |
| 分层边界 | 能区分核心设计系统与智能体验设计指导 | ≥90% |
| 能力边界 | 能区分能力声明、权限、审批和执行 | ≥90% |
| 主题与模式 | 能区分视觉映射和业务语义 | ≥90% |

按理解是否正确评分，不要求复述英文术语。

## 4. 观察记录

记录：

- 首次犹豫的位置；
- 参与者自行改写的术语；
- 错误状态推断；
- 预期存在但未找到的信息；
- 是否需要从“快速阅读”切换到“完整规范”；
- 用于恢复理解的路由和交互模式；
- 完成任务所需时间。

发现理解问题时，应先检查层级、命名和交互，再决定是否增加文字。
